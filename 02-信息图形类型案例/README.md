# 02-信息图形类型案例｜归档规则与案例分析模板

本目录按具体信息图形表达类型建立标签文件夹。**每个案例必须先做01五类数据逻辑判断，再做02具体标签归档**。两者是不同层级，不能颠倒或互相替代。

## 一、第一步：判断01五类数据逻辑
1. 编年型：以时间先后、事件顺序或历史演进为核心组织依据。
2. 层级型：以包含、隶属、等级、父子关系或整体到部分结构为核心。
3. 编目型：以类别、条目、属性或并列项目的归集与检索为核心。
4. 字母表型：以字母/字符顺序作为主要组织和检索规则。
5. 地理图形型：以地理位置、空间邻近、区域或路径关系为主要组织依据。

必须输出：主类型、次要逻辑（如有）、图中证据、判断理由、置信度。混合案例说明主次，不可只写“混合型”。

## 二、第二步：判断02具体案例标签
根据案例主要表达形式/用途，从本目录现有标签中选择最匹配的一类。无合适标签时先提出新增标签建议和边界说明。时间轴是呈现形式，编年型是数据组织逻辑；两者不能混为一谈。

## 三、案例文件组织
- 图片与分析文档同名、同目录：案例名称.jpg + 案例名称.md。
- 基础数据放入对应案例的data子目录，或采用统一案例编号前缀；原始数据与清洗/转换数据分开保存。
- 可复现代码、制图配置放入source目录，并注明运行环境和版本。
- 原始数据不可得时写明“原始数据未公开/未取得”；图像转录数据须标记为转录或估读，不得伪装为原始数据。
- 所有文件在Markdown中互相链接；注明来源、采集日期、版权/许可和数据局限。

## 四、每个案例分析文档模板
### 0. 案例信息
标题、作者/机构、来源URL、发布日期/获取日期、原始页码、版权/许可、原图文件、数据文件。

### 1. 01五类数据逻辑判断
主类型、次要逻辑、判断证据、理由、置信度；说明为何不属于相邻类型。

### 2. 02具体标签判断
归档标签、标签定义、选择理由、排除的相邻标签。

### 3. 基础数据集与数据结构
数据文件链接；数据实体、字段名、含义、类型、单位、样本范围、缺失值；数据属于原始/清洗/转换/估读哪一种；数据字典和局限。

### 4. 数据处理、统计与计算
筛选、清洗、排序、分组、聚合、归一化、统计口径、计算公式、统计图形类型；无统计计算时明确说明。

### 5. 制作方法与复现流程
数据准备 → 数据清洗/转换 → 统计计算 → 图表构建 → 视觉编码 → 排版标注 → 输出校验。注明已知软件、工具、关键参数；原作未知部分标记未知，推测复原另列。

### 6. 视觉编码提炼
以“视觉变量—数据字段/概念—表达含义—读图效果”逐项说明位置、长度、面积、角度、形状、色彩、明度、纹理、方向、连线、图标、文字、尺度和图例。

### 7. 信息架构与视觉叙事
信息分组、层级、顺序、关联、阅读入口、阅读路径、重点、比较关系、叙事节奏和结论。

### 8. 可迁移的设计方法
总结可复用的构图、编码、图表组合、标注、色彩、阅读引导和叙事策略；区分案例事实、跨案例归纳和待验证假设。
