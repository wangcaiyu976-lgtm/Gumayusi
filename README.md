# Gumayusi｜信息图形研究

本仓库建立从原始资料与基础数据、五类数据逻辑判断、案例标签归档、统计分析，到视觉编码、信息架构、视觉叙事和制作流程提炼的完整研究体系。

## 目录
- [01-信息图形数据逻辑](./01-信息图形数据逻辑/README.md)：五种数据组织逻辑的定义与跨案例归纳。
- [02-信息图形类型案例](./02-信息图形类型案例/README.md)：案例原图、基础数据集、分析文档及标签归档。
- [信息图形风格](./信息图形风格/)：风格研究；其中 [统计图形分析](./信息图形风格/统计图形分析/) 用于分析统计图形、数据结构和计算方法。

## 强制入库顺序
1. **先判断01五类数据逻辑**：编年型、层级型、编目型、字母表型、地理图形型。依据主要信息组织关系判断，不依据画面外观或图表名称。混合案例须指定主逻辑、次要逻辑并说明证据；不确定则标记待复核。
2. **再判断02具体案例标签**：从02现有标签中选择最匹配的表达类型。五类数据逻辑与02视觉/表达标签不是同一层级；时间轴、流程图、比较图等不能替代五类逻辑判断。无合适标签时先提出新增标签建议和边界。
3. **登记来源与基础数据集**：保存来源URL、作者/机构、标题、发布日期/获取日期、原始页码、版权/许可。能取得数据时必须上传原始数据及整理数据；优先CSV、TSV、XLSX、JSON，并附字段字典。
4. **分析数据与统计方法**：说明实体、字段、单位、样本范围、清洗、筛选、排序、聚合、统计口径、计算公式、转换方法及统计图表类型。区分原始、清洗、转换、推算和图面估读数据。
5. **提炼制作方法与流程**：按数据准备→清洗转换→统计计算→图表构建→视觉编码→版式编排→标注→校验记录工具、参数和可复现步骤。没有证据的原作软件/工具不得猜测，应写“未知”；复原方案与原作事实分开。
6. **提炼视觉编码**：说明位置、长度、面积、角度、方向、形状、色彩、明度、纹理、连线、图标、文字、尺度、图例如何映射数据字段或概念。
7. **总结信息架构与视觉叙事**：分析分组、层级、顺序、关联、阅读入口、阅读路径、重点强调、比较关系、叙事节奏与结论。
8. **归纳可复用方法并交叉检查**：提炼构图、编码、标注、色彩、图表组合和叙事策略；结论标注证据等级，并链接相关01定义及统计图形分析文档。

## 每个案例的入库文件
- 案例原图（保留原始出处与版权信息）。
- 同名Markdown分析文档（完整填写02模板）。
- 基础数据集：优先原始数据；原始数据不可得时上传可核验的转录/整理数据并标明性质；若未公开则明确写明，不得伪造。
- 数据字典与来源说明；必要时附清洗后数据、计算表、代码或制图配置。
- 若案例没有量化数据，仍需保存结构化内容/字段清单，并解释不适用统计数据集的原因。

## 证据规则
- 观察事实、可复算结果、推断复原、待验证假设必须明确区分。
- 图面估读数据不能冒充原始数据；推断出的制作软件不能写成事实。
- 跨案例反复出现的规律才提升为设计原则；反例出现时注明适用范围并修订。
- 图片、文档、数据文件使用统一案例编号/文件名前缀并互相链接。
