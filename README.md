# Gumayusi｜信息图形研究

本仓库用于建立一套以**案例观察 → 五类数据逻辑判断 → 信息图形类型归类 → 数据集整理 → 统计图形分析 → 视觉编码分析 → 视觉叙事总结 → 制作方法复盘**为核心的信息图形研究方法。

## 目录

- [01-信息图形数据逻辑](./01-信息图形数据逻辑/README.md)：五类基础数据／信息组织逻辑的定义与判断标准。
- [02-信息图形类型案例](./02-信息图形类型案例/README.md)：案例图片、类型标签、案例分析和基础数据集。
- [信息图形风格](./信息图形风格)：视觉风格与统计图形研究。

## 强制案例分析顺序

每个新案例必须严格按以下顺序判断和记录，不得跳过前置分类：

1. **01｜先判断五类数据逻辑**：编年型、层级型、编目型、字母表型、地理图形型。判断依据是信息／数据的主要组织关系，而不是图面外观。若一个案例包含多种逻辑，指定主逻辑并记录次要逻辑及理由。
2. **02｜再判断信息图形类型标签**：从 `02-信息图形类型案例` 已有标签中选择最匹配的一类；必要时标注主标签、次标签。五类数据逻辑与信息图形表现类型是两个不同层级，不可混为一谈。
3. **03｜分析基础数据集与数据处理**：识别实体、字段、单位、时间／空间范围、分类、排序、缺失值、统计口径、计算和转换。尽可能整理可复用的 CSV、XLSX 或 JSON 数据文件。
4. **04｜提炼视觉编码**：分析位置、长度、角度、面积、体积、方向、形状、符号、色彩、纹理、文字、尺度、连线、空间布局等视觉变量分别映射了什么数据。
5. **05｜提炼视觉叙事**：说明主题与核心观点、信息层级、阅读起点和路径、分组／转场、重点强调、比较关系、结论及其证据。
6. **06｜总结特性、制作方法与流程**：说明适用场景、优势与局限、所需数据、数据清洗与计算、图形构建、视觉编码、版式编排、标注和校验步骤；区分原作可观察事实与我们的推测性复原。

## 入库硬性要求

- 每个案例至少保存：**案例图片 + 同名 Markdown 分析文档**。
- **基础数据集必须一并入库**：优先保存可追溯的原始／整理后数据，格式优先 CSV、XLSX、JSON；并附数据字典、来源、采集日期、单位、清洗／计算过程和许可信息。
- 若原作未公开数据，不得伪造数据或把估算值冒充原始值。应记录“原始数据未公开”；如能从图面可靠转录，则另存“图面转录数据”，注明转录方法、估读误差和不确定性。
- 若案例不含量化数据，仍应保存可复用的结构化内容／字段清单；并在文档中说明不适用统计数据集的原因。
- 图片、说明文档、数据文件使用统一案例编号与文件名前缀，确保相互关联；数据文件可以放在对应类型目录下的 `data/` 子目录，或与案例文档并列，且必须在 Markdown 中链接。
- 每个案例必须记录来源 URL／书目信息、原始页码或出处、版权／许可状态；来源不明时标记待核实。
- 不删除已有案例；分类不确定时标记“待复核”，不得为了凑类别强行归类。

## 每个案例的统一分析维度

- A. 基础数据逻辑与五类判断：数据实体、字段、关系、组织依据、主／次逻辑及判断理由。
- B. 信息图形类型标签：主标签、次标签、归类依据。
- C. 基础数据集与统计方法：数据来源、字段、统计口径、计算／转换、统计图形；无统计计算时明确说明。
- D. 视觉编码：视觉变量及其与数据的映射关系。
- E. 信息架构：分组、分层、排序、关联和空间组织。
- F. 视觉叙事：阅读路径、叙事节奏、重点、比较和结论。
- G. 制作方法与流程：工具／技术（有证据才填写）、数据处理、图形生成、设计制作、校验和复现步骤。
- H. 设计评价：适用场景、可读性、优势、局限和可迁移的方法。

> 原则：先看数据关系，再看图形标签，最后分析视觉表现。图形外观相似不代表数据逻辑相同；不得把“编年型数据逻辑”与“时间轴视觉形式”等同。
